# Getting Help

Thanks for using `mcp-behave`. This page explains where to ask questions and how to provide information that helps diagnose problems.

## Usage Questions

For questions about installation, configuration, supported transports, tracing behavior, or interpreting a report:

1. Check the [README](README.md) and the relevant project documentation first.
2. Search existing [issues](https://github.com/navid72m/mcp-behave/issues) for a similar question or problem.
3. If you still need help, use the **Usage question** issue form. Include the command you ran and the relevant output, after removing secrets and personal information.

Please keep questions focused and provide enough context for someone else to reproduce the situation.

## Bug Reports

Use the **Bug report** issue form for reproducible defects. Include the `mcp-behave` version, operating system, Python version, installation method, command, expected result, actual result, and relevant logs where possible.

For a general usage question that is not a bug report or feature proposal, use the **Usage question** issue form.

## Feature Requests

Use the **Feature request** issue form to explain the problem you are trying to solve, the proposed behavior, and any alternatives you have considered. Smaller, clearly scoped proposals are easier to discuss and review.

## Security Issues

**Do not report security vulnerabilities in public issues.** Follow the private reporting instructions in [SECURITY.md](SECURITY.md), using GitHub Private Vulnerability Reporting or the security contact listed there.

## What to Include — and What to Remove

Helpful diagnostic information includes:

- `mcp-behave` version and installation method (`pip`, `uvx`, `npm`, or `npx`).
- Operating system and version, architecture, and Python version.
- The command and configuration relevant to the problem.
- A minimal reproduction, expected behavior, actual behavior, and relevant error output.

Before posting, remove API keys, access tokens, passwords, private keys, personal data, and sensitive local paths from logs and configuration snippets. Do not attach real credential files or production data.

## Maintainer Availability

`mcp-behave` is maintained primarily by an individual maintainer. Support is provided on a best-effort basis; there is no guaranteed response time or service-level agreement. Clear, reproducible reports help issues get attention sooner. Community contributions and independently verified answers are welcome.
